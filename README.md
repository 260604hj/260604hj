# 📘 우리 팀 웹앱 — 작업 가이드 (비전문가용)

코딩을 전혀 몰라도 괜찮습니다. 이 문서대로만 따라 하면 누구나 우리 팀 웹앱을 **수정하고 인터넷에 올릴 수** 있습니다.

> 우리 사이트 주소: **https://260604hj.github.io/260604hj/**

---

## 0. 한눈에 보는 큰 그림

용어 4개만 알면 됩니다.

| 말 | 쉽게 말하면 |
|----|-------------|
| **GitHub (깃허브)** | 우리 팀 **공용 코드 창고**. 여기 올린 파일은 자동으로 웹사이트가 됩니다. |
| **내 PC의 폴더** | 그 창고를 내 컴퓨터에 **복사해 둔 것**. 여기서 편집합니다. |
| **Supabase (수파베이스)** | **데이터 창고**. 메모처럼 앱에서 저장한 내용은 GitHub가 아니라 여기에 들어갑니다. |
| **배포 (deploy)** | 내가 수정한 걸 GitHub로 **올려서 웹에 반영**하는 것. |

작업은 언제나 이 **3단계 반복**입니다:

```
 ①  받기   →   ②  수정   →   ③  올리기   →  (자동)  웹사이트 반영
 (최신본)      (클로드로)     (클로드로)          1~2분 뒤
```

## 2. 평소 작업 — 클로드에게 세 마디

### ① 편집 전 → "최신버전 받아줘"  ⭐꼭!
다른 PC나 팀원이 바꾼 **최신 내용을 먼저 받아옵니다.** 이걸 건너뛰면 충돌이 날 수 있어요.

### ② 수정 → 클로드에게 시키기
파일을 직접 못 고쳐도 됩니다. 클로드에게 부탁하세요. 예:
> "260604hj 폴더의 index.html에 '문의하기' 탭을 추가해줘."

### ③ 올리기 → "배포해줘"
바뀐 내용이 **자동으로 깃허브에 올라가고**, 1~2분 뒤 사이트에 반영됩니다.

> 클로드 없이 직접 하려면, 이 폴더에서 터미널을 열고:
> ```
> git pull origin main                                          (받기)
> git add -A  →  git commit -m "무엇을 바꿨는지"  →  git push origin main   (올리기)
> ```

## 3. 파일은 어디에, 어떻게 두나

폴더를 이렇게 정리해서 쓰는 걸 권장합니다(없는 폴더는 만들면 됩니다):

```
260604hj/
├─ index.html             ← 메인 페이지 (앱 목록)
├─ miniapps/              ← 앱 모음
│  ├─ memo.html
│  ├─ admin-memo.html     ← 로그인 필요
│  ├─ drawing-memo.html   ← 로그인 필요
│  ├─ ascii-comic.html    ← 로그인 필요
│  └─ old/                ← 예전 앱 보관
├─ supabase/
│  ├─ migrations/         ← 데이터베이스 구조 기록 (.sql)
│  └─ functions/          ← Supabase 서버에서 도는 코드 (summarize, ascii-comic)
├─ IMG/                   ← 이미지 모음
├─ data/                  ← 엑셀(xlsx), csv 등 데이터 파일
└─ README.md              ← 이 안내문
```

| 종류 | 어떻게 |
|------|--------|
| **HTML 코드** | 폴더에 그대로 두고 클로드로 수정 |
| **이미지** | `IMG/` 폴더에 넣고, 클로드에게 "이 이미지를 화면에 넣어줘" |
| **엑셀·CSV 데이터** | `data/` 폴더에 두기 (단, 아래 ⚠️ 주의사항 확인) |

파일을 추가·삭제·이동해도, 마지막에 **"배포해줘"** 한마디면 그대로 깃허브에 반영됩니다.

## 4. Supabase — 데이터 창고

- 앱에서 저장한 내용(메모 등)은 **Supabase에만** 있습니다. 이 폴더와 깃허브에는 데이터가 없습니다.
- `supabase/migrations/` 의 `.sql` 파일은 **표와 규칙을 만든 기록**입니다.
  Supabase 대시보드의 SQL Editor에서 **번호 순서대로 한 번씩** 이미 실행했습니다.
  다시 실행하면 "already exists" 오류가 납니다.
- 구조를 바꿀 때는 기존 파일을 고치지 말고, **다음 번호로 새 파일**을 만들어 한 번 실행합니다.
- 새 Supabase 프로젝트로 옮길 때는 `001` 부터 차례로 실행한 뒤,
  `002_admin_memos.sql` 맨 아래 주석의 관리자 등록 줄을 따로 실행합니다.
- `supabase/functions/` 는 Supabase 서버에서 실행되는 코드(Edge Function)의 원본입니다.
  대시보드의 Edge Functions 에 붙여넣어 배포합니다. 이 폴더를 고쳐도 배포하기 전에는 서버에 반영되지 않습니다.
- 키는 두 종류입니다.
  - **Publishable key** (`sb_publishable_...`) — 공개용. html 에 넣어도 됩니다.
  - **Secret key** (`sb_secret_...`) 와 **데이터베이스 비밀번호** — 절대 이 폴더에 넣지 마세요.
  - **Gemini API 키** 도 같습니다. 대시보드의 **Edge Function Secrets** 에 `GEMINI_API_KEY` 로만 넣습니다.

## 5. ⚠️ 꼭 지켜야 할 주의사항 (가장 중요!)

### 🔴 이 창고는 "공개(public)"입니다 — 올리는 모든 것이 인터넷에 공개됩니다
- **비밀번호 · 개인정보 · 대외비 회사자료 · 고객 데이터는 절대 올리지 마세요.**
- 한 번 올라가면 나중에 지워도 인터넷 어딘가에 남을 수 있습니다.
- 민감한 데이터를 저장해야 한다면, 파일로 올리지 말고 **Supabase처럼 로그인 규칙이
  걸린 데이터베이스**에 저장해야 합니다.

### 🔴 큰 파일은 올라가지 않습니다
- 한 파일이 **100MB를 넘으면 거부**됩니다(50MB만 넘어도 경고).
- 대용량 원본(큰 PPT, CAD 도면, 동영상 등)은 깃허브에 넣지 말고 따로 보관하세요.
- 웹에 쓸 이미지는 적당히 용량을 줄여서(수백 KB) 넣으세요.

### 🟡 편집 전에는 항상 "최신버전 받아줘" 먼저
안 그러면 다른 PC나 팀원의 작업과 충돌할 수 있습니다.

### 🟡 "push 실패"가 떴다면
→ "최신버전 받아줘" 한 뒤, 다시 "배포해줘". (대부분 자동 해결)

### 🟡 "Permission denied to (다른 계정 이름)" 이 떴다면
이 PC에 다른 깃허브 계정 로그인이 저장돼 있는 경우입니다. 클로드에게 이 오류를 보여주면
저장소 주소에 `260604hj` 계정 이름을 넣어서 해결해 줍니다.
